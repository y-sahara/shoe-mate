# 技術選定

## 構成

| 項目 | 選定 | 理由 |
|---|---|---|
| デプロイ先 | Cloudflare Pages | 希望条件。静的 SPA のホスティングとの相性が良い |
| フロントエンド | React + Vite（SPA） | Next.js は不採用。アニメーション重視のアプリでは SSR/ハイドレーションがむしろ邪魔になりやすく、個人向けツールで SEO メリットも薄いため |
| バックエンド | 基本的に不要（必要時は Cloudflare Workers + Hono） | Supabase が DB・認証・ストレージ・RLS を提供するため、独自サーバーは「写真→アニメーション変換」等の重い処理が必要になった場合のみ検討する |
| DB / ストレージ / 認証 | Supabase（まずはこれで統一） | DB・Auth・Storage がセットで揃っており、立ち上げが早い。パフォーマンス面で課題が出たら画像配信のみ Cloudflare R2 / Images への移行を検討 |

## 補足: Hono とは

TypeScript/JavaScript で書く軽量 Web フレームワーク（バックエンド言語ではない）。Express のようにルーティングや API を定義するためのもので、Cloudflare Workers 等のエッジ環境で動くように設計されている。本アプリでバックエンド処理が必要になった際の選択肢として採用。

## SEO についての方針

- アプリ本体（ログイン後のシューズ一覧・記録画面）はログインが必要な非公開データであり、検索エンジンにインデックスさせる対象ではないため、SPA のままで問題なし
- 将来、他ユーザーへの公開に向けてアプリを知ってもらうための紹介ページ（LP）が必要になった場合は、SPA 本体とは切り離し、シンプルな静的ページを別途用意して meta tag・OGP 等の SEO 対策を行う
- 現時点では LP の作り込みは不要。方針のみ記録しておく

## 写真アニメーションのライブラリ方針

- Framer Motion・Three.js (React Three Fiber) ともに npm パッケージ追加だけで React + Vite の現スタックにそのまま導入可能（Next.js ではなく Vite SPA を選んだことで、これらとの相性はむしろ良い）
- **Framer Motion**: 通常の React コンポーネントとして使え、SSR 前提もないため注意点なし。フェード・スライド・ホバー変形など 2D 寄りの表現はこれで十分
- **Three.js / React Three Fiber**: WebGL を使うため以下を考慮
  - バンドルサイズが大きい → Vite のコード分割（遅延 import）でシューズ詳細画面のみ読み込む
  - スマホでの描画負荷・バッテリー消費増に注意
  - 実装難易度が Framer Motion より高い
- **進め方**: まず Framer Motion で写真の見せ方を作り込み、物足りない部分（シューズ詳細のメインビジュアル等）のみ Three.js を部分導入する段階的アプローチとする。採用可否は実装フェーズで試しながら判断する

# 画面設計

[requirements.md](./requirements.md)・[data_model.md](./data_model.md) を元にした画面構成。

## 画面一覧

| # | 画面名 | 概要 |
|---|---|---|
| 1 | ログイン / サインアップ | Supabase Auth によるログイン |
| 2 | シューズ一覧 | 自分の登録シューズをカード形式で一覧表示（アニメーション表示の起点） |
| 3 | シューズ詳細 | 1足分の情報・使用記録の履歴・アニメーション表示 |
| 4 | シューズ登録・編集 | 新規登録／情報編集フォーム |
| 5 | 使用記録の追加 | 距離更新の入力（シューズ詳細からモーダル等で呼び出す想定） |

## 1. ログイン / サインアップ

- メールアドレス + パスワード、または Supabase Auth のソーシャルログイン（Google 等、要検討）
- 個人利用前提のため、最低限の UI でよい

## 2. シューズ一覧（ホーム）

- 使用中（`status = active`）のシューズをカード表示（写真・名前・累計距離・買い替え目安までの残り距離をプログレスバー等で表示）
- 引退済み（`status = retired`）シューズは別セクションまたはタブで分離表示
- カードタップでシューズ詳細へ遷移
- 新規登録ボタンを配置

## 3. シューズ詳細

- メイン写真（`is_primary = true`）を大きく表示 → **ここで写真アニメーションを表現する最重要画面**
- 基本情報（ブランド・モデル・購入日・使用開始日）
- 累計走行距離／買い替え目安距離（プログレスバー、達した場合はアラート表示）
- 使用記録の履歴（テーブル or タイムライン表示、`recorded_at` 降順）
- 「使用記録を追加」ボタン
- 編集・引退（ステータス変更）・削除への導線

## 4. シューズ登録・編集

- フォーム項目: 名前、ブランド、モデル、購入日、使用開始日、買い替え目安距離（デフォルト500km）、メモ、写真アップロード（複数枚、並び替え可能）
- 写真アップロードは `shoe_photos` への複数レコード登録・`sort_order` の設定を伴う

## 5. 使用記録の追加

- フォーム項目: 記録日（デフォルト今日）、累計走行距離、メモ（任意）
- 入力後、シューズ詳細の履歴とグラフ（累計距離の推移）に反映

## 画面遷移の方針

```
ログイン
  └→ シューズ一覧（ホーム）
        ├→ シューズ詳細
        │     ├→ 使用記録の追加（モーダル）
        │     └→ シューズ編集
        └→ シューズ新規登録
```

- 個人向けのシンプルな構成のため、画面数を増やしすぎずモーダル・ドロワーで補助的な操作（記録追加・編集）を完結させる

## 今後の検討事項

- 写真アニメーションの具体的な見せ方（シューズ一覧でのホバー/タップ時の動き、詳細画面での表現）を技術選定（Framer Motion / GSAP / Three.js 等）と合わせて詰める
- 累計距離の推移グラフの要否・ライブラリ選定
- レスポンシブ対応方針（スマホ利用がメインか、PCも想定するか）
